# WinUI 移植中真正影响结果的问题

下方表格保留早期固定局部拉扯阶段的经验；当前示例按更新后的需求使用小幅跟手/松手回原位，详见文末。

这份复盘记录从 Flutter 参考移植到 WinUI、接入桌面应用再提取独立示例的经验。实现位于 [WinUI 示例](../examples/winui-liquid-glass/)，通用决策已整理进 [skill](../skills/flutter-liquid-glass/SKILL.md)。

| 观察到的问题 | 原因与修正 | 验证方式 |
| --- | --- | --- |
| 玻璃内部仍有白色/实体填充 | shader 之外还有模板、原生选择态、回退层和描边；按最终合成顺序排查 | 实际窗口截图，不只导出 shader |
| 右侧出现黑条 | 捕获包括越界子元素，直接将整张 bitmap 宽度拟合到布局宽度挤入透明留白 | 保留原生像素比例，验证带偏移的 150% DPI |
| 非 100% DPI 下复杂采样失败 | Direct2D 效果图出现隐式 DPI 补偿 | 96-DPI 物理像素目标中计算，最终映射 XAML DIP |
| 程序画面与 `PrintWindow` 不同 | 窗口捕获返回旧的实体回退画面 | 检查前台、解锁状态，用可见客户端捕获 |
| 固定卡片像在斜着滑动 | 即使中心不动，整块逆矩阵拉伸/斜切仍不符合局部拉扯 | 改为抓取边缘附近的有限影响场；检查远角、对边和主体不变 |
| 右侧原生卡片不如透镜有弹性 | 外层 `Grid.CornerRadius` 裁掉了向外鼓起的部分；同时局部弹簧阻尼偏大 | 将材质圆角独立为 `SurfaceCorners`，移除外层裁剪；加入按压鼓起与可见反向回弹，原生截图断言布局外像素变化 |
| 自动化指针到了，卡片没收到移动 | `SetCursorPos` 在本环境只移动光标，捕获中的 `PointerPoint` 仍是旧坐标 | 发送真实鼠标移动事件；再同时核对轨迹、画面形变和业务输入 |
| 面板动画影响内部按钮 | 父面板与子按钮争夺事件或同时缩放 | 每个原生控制只分配一个光学交互所有者，保留 Click/编辑/滚动 |
| 最大化后人物远离任务卡或底部截断 | 固定位置/缩放与原图只有半身混淆 | 检查原始素材，按可用空间贴近卡片并按用户选择遮挡底部；不虚构缺失部分 |
| 本机可构建，独立项目缺资源/PRI 重复 | 忽略 manifest、外部 Link 改成本地文件后仍重复 Include | 检查干净克隆；本地默认 Content 用 Update；调用 App.InitializeComponent |
| 自动截图缺阶段或沿用旧文件 | 首帧资源未就绪或只检查文件存在 | 预热后计时，每张图片核对本次时间戳 |
| 模型检查通过却无法证明手势 | 直接设置模型或 UIA Invoke 没有走真实指针路由 | 分开记录模型、GPU、原生鼠标三类证据 |

“固定位置”不能仅靠中心坐标测试。旧的全局形变可保持面积中心，但仍让整块边缘倾斜；现在固定组件不使用整体位置、缩放或旋转状态，只改变抓取点附近的距离字段。移动导航透镜仍允许位置运动，二者不应混用。

示例提供真实输入脚本与独立 GPU 探针。37 项单测覆盖持续拉扯、释放、再次抓取、反向、30/60/120/144 Hz、绘制留白、抓取边缘与可见回弹；14 项 GPU 检查涵盖场景位移、前景、alpha、光照、偏移/DPI及局部形变。`-Capture` 的状态序列是模型驱动，鼠标脚本另行记录按住、反向、释放后的八帧余震和稳定态。

2026-11-24 在 Windows x64 / 110 DPI 下完成原生鼠标验证：抓取点附近产生布局外的可见鼓起，正文坐标固定，鼠标按钮恰好触发一次点击，输入框仍可编辑。随后同步到 `yunkao` 主程序并实测任务卡与诊断卡。截图为当前窗口的客户端区域，未展示或上传业务账号与设置内容。

这些经验针对已观察到的 WinUI/Flutter 路径。skill 给出其他平台的适配决策，不保证未经运行的后端具有相同像素、性能或外部内容捕获能力。

## 后续参考对齐与清晰玻璃

用户后续明确选择 design-systems 的 tether 整体随动，再要求缩小幅度。当前示例按该最新契约实现：整块卡片/文字一起运动，卡片/按钮上限 12/4 DIP、指针增益 0.18，松手归位；原来的“正文绝不动”测试只适用于局部拉扯模式。参考版本 7a424c93，直接执行上游 tick 生成 210 帧轨迹，与 C# 实现比较。39 项 Demo 测试、21 项 GPU 检查与真实鼠标/键盘验证分别保留证据。

实际控件曾比独立透镜平：CPU 使用 ComputeSharp Float4 `/=` 导致上传的 inverse uniform 全零，法线、折射、高光消失。改为标量运算后构造 Float4，并在 NativeCapture 中核对实际 uniform；独立 shader 探针不能替代宿主检查。面板圆角 28 DIP、blur 0.25、按短边扩宽曲面带，能在文字/网格/人物处观察到弯折。深色导航还需关闭按压椭圆泛光/内阴影、tint 和 blur，避免中心形成灰雾。

原生按钮仅转移 capture 仍会在 release 触发 click；真拖动时临时抑制 Release 路径，事件结束后恢复，轻点/键盘保持原语义。捕获丢失应过滤事件来源，不能把旧所有者冒泡的 lost capture 当作当前手势结束。

新增玻璃开关：按住透明玻璃、左右拖动连续变色、松手提交状态并恢复普通滑块，Esc 取消、键盘和 UIA TogglePattern 正常。模型与真实输入各有验证，不在设置预览途中保存。WinUI ToggleSwitch sealed，因此用独立 Control 与明确 TogglePattern 语义接入现有 IsOn/Toggled 业务回调。
